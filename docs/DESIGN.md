# HIGHLIGHT Studio 官网重构说明

纯静态站点，无构建步骤，直接部署到 GitHub Pages（`CNAME: h-s.tech`）。把 `site/` 下的全部文件放到仓库根目录即可。

```
site/
├─ index.html          首页：00 品牌 → 01 CubeXDesktop → 02 产品 → 03 团队 → 04 加入 → 页脚揭幕
├─ join.html           加入我们：九个岗位 + 联系方式
├─ css/site.css        全部样式（约 30KB，未压缩）
├─ js/main.js          入口：滚动调度、胶囊导航（收起/展开）、下拉菜单、章节指示、揭示、高亮
├─ js/hero.js          首屏：120° 粒子圆弧 + 流星 + 沿弧转动后组装的标语      （直接加载）
├─ js/cubex.js         CubeXDesktop：真实渲染层 iframe + 组件飞入拼合          （直接加载）
├─ js/cards.js         产品卡指针高光                                        （按需 import）
├─ js/footer.js        页脚揭幕可见性控制                                    （按需 import）
├─ js/distort.js       trae.cn grid-distortion 的 WebGL2 复刻                （按需 import）
├─ cubex-app/          CubeXDesktop 原软件的渲染层构建产物（iframe 内跑的就是它，约 1.8MB，按需加载）
└─ assets/             字体、logo、头像、页脚字标（全部 WebP，显式宽高）
```

本地预览：`cd site && python -m http.server 8000`，打开 http://127.0.0.1:8000 。因为用了 ES module，不能直接双击 html 打开；CubeXDesktop 的窗口是同源 iframe，也必须走 http。

## 1. 参考网站的做法与取舍

| 站点 | 观察到的做法 | 本站采用 |
|---|---|---|
| Apple | 一屏一个观点；超大标题配短副文；留白优先，一屏只有一个信息重心 | 每节只有一个标题、一句导语；首屏标题占满一屏，其余元素退到底部 |
| Linear | 深色底配细线分隔，层级靠灰阶而不是颜色；动效短（200–400ms）、缓出；入场只做轻微位移和淡入 | 沿用旧站灰阶 tokens；揭示动画只位移 28px；交互反馈 300–500ms |
| Vercel | 网格与 1px 线条做结构；等宽字体标注元信息；首屏几乎不加载 JS | 全站用 Geist Mono 做编号和标签；首屏只执行 main.js（约 9KB），其余模块按需加载 |
| Stripe | 卡片网格疏密有致（不同宽度混排）；指针高光让静态卡片有“手感” | 产品区 12 栏网格中混排 7/5、5/7、4/8、6/6 宽度；指针径向高光 |
| trae.cn | 页脚字标用 `position:fixed` 藏在内容下方，滚到底时被“揭开”；字标随鼠标做网格扭曲 | 结构与算法 1:1 复刻，见第 4 节 |

共同的规律：留白比装饰多；一次只动一个东西；动画服务于阅读顺序；首屏不等 JS。

## 2. 叙事结构

整页按“我们是谁 → 我们做的东西 → 做东西的人 → 你”展开。每节结尾有一行衬线斜体的过渡句（`.bridge`），把下一节引出来，避免模块之间硬切。

| 章节 | 标题 | 过渡句 |
|---|---|---|
| 00 品牌 | 以人文 / 铸科技（滚动时出现） | — |
| 01 CubeXDesktop | 把 AI、代码、文档放进同一个窗口。 | — |
| 02 一桌作品 | 软件、服务器、频道，都摆在同一张桌上。 | 东西是人做出来的。下面是做这些东西的几个人。 |
| 03 几个人 | 人不多，每个人都身兼几份活。 | 名单还很短，留着位置给下一个人。 |
| 04 下一位 | 故事写到这里，下一行可以是你。 | → 页脚揭幕 |

左下角章节指示（`#chapter`：红色编号 + 章节名）随阅读位置切换，切换时名称淡出再淡入；导航胶囊的 scrollspy 同步高亮。章节指示在首屏不出现，页脚字标露出时让位。

## 3. 动画方案

| 动画 | 触发 | 实现 | 属性 |
|---|---|---|---|
| 首屏：正圆 120° 粒子穹顶 + 流星（canvas） | 常驻，只在首屏可见时跑 rAF | 扇面撒点 + 一条连续密度/亮度曲线（同 ASCII 空态），不铺任何填充色；按亮度分 10 桶批量 fill | canvas 绘制 |
| 首屏滚动：居中的 logo 渐隐 → 标语六个字沿弧自左向右流转 → 到达弧顶后逐个飞向页面中心组装成两行大字 | 滚动 | 共享 rAF，弧上位置与中心槽位插值，逐字错开 0.026 进度 | transform / opacity + canvas |
| CubeXDesktop：窗口内是原软件的真实渲染层（同源 iframe）；底色常驻，14 个真实部件各自从窗口右侧之外飞入、拼回原界面 | 滚动（钉住 2.05 屏） | 每块整块出界（左边缘越过窗口右边界 +56px），`translate3d` + 微旋转 + 0.95→1 缩放，三次方减速不回弹；侧栏与标题栏纯水平推进，主区带浅弧；飞行中挂承载卡，落位随位移归零；全部就位扫过一道高光 | transform / 伪元素 |
| 进入视口揭示 `[data-rv]` | IntersectionObserver 触发一次 | CSS transition，同组兄弟依次错开 70ms | transform / opacity |
| 关键词高亮扫过 `.hl` | 进入视口一次 | `background-size` 0→100%，只变化一次 | 背景 |
| 产品卡高光 | pointermove（委托） | rAF 写 `--mx/--my` | 卡片内伪元素 |
| 菜单 | 点击 / Esc | 链接逐行上推，焦点限制在菜单内，关闭后焦点还给按钮 | transform / opacity |
| 页脚揭幕 + 网格扭曲 | 滚到页底 / mousemove | fixed 层 + WebGL2，见第 4 节 | GPU |

缓动沿用旧站：`--ease: cubic-bezier(.16,1,.3,1)`（expo-out，用于入场），`--ease-io: cubic-bezier(.7,0,.3,1)`（用于遮罩和扫描）。

## 4. 页脚：trae.cn 效果复刻

来源是 trae.cn 线上包 `async/86826.js` 中的 `grid-distortion` 组件，以下参数取自源码：

- **结构**：外层占位高度为 `(min(100vw,1600px) - 2·padX) / aspect + 2·16px`；内层 `position:fixed; bottom:0`，同样高度，红底。上方 `.page` 和 `.foot-body` 的 `z-index:1` 加不透明背景盖住它，滚动到底时占位区进入视口，字标从内容下方露出来。trae 的宽高比是 3.83228，我们的字标是 1800×446，宽高比为 4.0359。左右内边距按断点取 16 / 24（≥744px）/ 32px（≥1280px），与 trae 相同。
- **算法**：
  - 数据纹理为 15×15 的 RGBA Float，初值 `255·rand − 125`。
  - 每帧先对所有格子乘以 0.9；然后对半径 `15·0.25` 内的格子叠加 `100·0.15·v·min(p/√f, 10)`，其中 v 是指针速度。
  - 片元着色器：`texture(uTexture, vUv − 0.02·data.rg)`。
  - 数据纹理用 NEAREST 采样，所以位移呈块状；字标纹理用 LINEAR 采样。
  - 初始随机值让字标首次出现时是“碎”的，约 0.5s 后自行复原，这是 trae 的原始效果。
- **与原版的差异（只改调度，不改效果）**：
  1. 不用 three.js（约 600KB），改用约 200 行原生 WebGL2 实现。
  2. 原版的 rAF 永不停止。本站在离屏时停帧，数据收敛（变化量 < 1e-3）后也停帧，有鼠标移动时再唤醒。
  3. 原版每帧都在推进，在 120Hz 屏幕上衰减速度会翻倍。本站固定按 60Hz 推进，各种屏幕上的手感一致。
  4. 不支持 WebGL2、触屏设备、开启减少动态效果时，显示同一张静态字标。fixed 层在接近视口之前保持 `visibility:hidden`，不参与合成。
  5. WebGL 上下文丢失时，移除 canvas，退回静态图。

## 5. 性能优化手段

**首屏**
- 没有构建步骤，也没有框架。首屏只请求 HTML + 1 个 CSS + `main.js`，HTML/CSS/JS 合计约 96KB（未压缩，GitHub Pages 会 gzip）。
- 只 preload 一份标题字体（Bricolage Bold）。四份字体都用 `font-display: swap` 和 `unicode-range` 限定拉丁字符，中文走系统字体，不下载 CJK 字体。
- `<head>` 内一行同步脚本在首帧前给 html 加上 `motion` 或 `still` 类，避免动画状态闪烁。
- 揭示动画的初始隐藏态挂在 `html.rv` 上，这个类由 JS 添加。脚本失败时内容照常显示，不会出现空白页。

**资源**
- 所有图片都是 WebP，并写明 `width` / `height`，不产生布局偏移。首屏以下的图片都加了 `loading="lazy"` 和 `decoding="async"`。
- 首屏 canvas 的 DPR 上限为 2，候选点数按穹顶面积给（约 2.4k–26k），按密度曲线筛完剩下约 1.6k–18k 个粒子；按亮度分 10 桶、桶内再分「方点 / 圆点」两批，拖尾只在真正滚动时每 26 个抽样一次。实测帧间隔桌面 18.3ms / 手机 16.7ms。

**按需初始化**
- `cards.js`、`footer.js`、`distort.js` 都在对应版块接近视口时才 `import()`。`hero.js` 与 `cubex.js` 随入口一起加载（合计约 9KB）。CubeXDesktop 的界面（约 1.8MB 构建产物，含一个按需拉取的 embeddings chunk）在版块接近视口 700px 时才给 iframe 赋 `src`，只看首屏的访客完全不下载。

**60fps**
- 只动画 `transform` 和 `opacity`；逐帧状态由 JS 写 transform，状态切换交给 CSS transition 或 keyframes。
- 所有滚动逻辑共享一个 rAF。scroll 事件只负责排队，滚动时不读布局。尺寸只在 resize（120ms 防抖）和 ResizeObserver 回调里读取并缓存。
- 各模块通过 IntersectionObserver 注册和注销滚动任务，离屏后完全不跑。
- 指针类交互（越权者悬停、卡片高光）合并到 rAF，进入元素时缓存 rect，移动时不触发布局。
- 入场时间轴用 CSS keyframes，运行在合成线程，主线程忙时也不掉帧。
- 首屏 canvas 离屏即停 rAF；滚动只更新一个进度值，重绘一帧。

**降级**
- 系统开启“减少动态效果”后（浏览中切换也实时生效）：所有动画和过渡时长归零；关键词高亮直接显示最终态；越权者直接显示最终状态；页脚显示静态字标。
- `@media (hover:none)` 下关闭指针高光；触屏不初始化 WebGL。
- 键盘：提供跳到正文链接；全局 `:focus-visible` 红色描边；菜单内焦点循环，Esc 关闭。

## 6. 已验证

在 Chrome 中测试了三种情况：桌面 1440×900、移动 390×844、桌面加减少动态效果。
- 控制台无报错，无失败请求，无横向溢出。
- 页脚 WebGL 在前两种情况下都已初始化，减少动态效果时退回静态图。

## 视觉定稿（第四轮）

- **首屏**：取一个**正圆**的 120° 弧段（即半圆的 2/3），不是椭圆。`R = W/√3`、圆心在屏幕底边下方 `R/2`，于是弦正好是屏幕底边、两端落在左下角与右下角，弧高 `R/2`。
  - 粒子只有一层，形状完全由粒子本身的密度堆出来：`dens = 0.40 + 0.54·t²`（圆内 0.40、弧线 0.94），亮度 `al = 0.10 + 0.24·t^1.5 + 0.26·t⁷`。屏幕上能看到的「圆里面」其实只是半径 0.5 以外的一段，所以内圈不能压太低，否则半圆正中会空出一大片；`t⁷` 那一项让最外一圈明显亮一档，但它跟着粒子一起转，是「越靠边越亮」，不是画上去的一圈死环。
  - 界外 `0.22·fade³`、亮度 `0.4·fade^1.4`，羽化带 `FEATHER = 0.22`，而且**界外一颗浮尘都不留**——外面只要还剩散点，轮廓立刻被糊掉。曾经在界内垫过一层离屏径向雾，结果是整个半圆变成一块 1.8%–6.2% 的灰白面、并在 `r = R` 处硬切，看上去就是「一层半透明白色半圆」，已彻底删除；角落的黑交给「筛剩候选点里保留 24% 的极淡细尘」。
  - 粒子是 0.3–1.9px 的圆点；小于 1.3 设备像素的直接画成方点，省掉大量 `arc` 路径。候选点数按穹顶面积给（`R²·0.038`），宽屏窄屏颗粒密度一致。**页面停住时粒子完全不动**（早期版本有 0.02 rad/s 的自转漂移，看着像噪点在爬，已去掉）；只有滚动时整场才绕圆心流转。
  - 流星斜落，**碰到穹顶即消失**（与圆心的距离 ≤ R 时立刻重生），不会穿进球里。
  - logo 用 2190×593 的原始字标导出 1400px WebP（把黑字改白、H 保留红色），桌面最宽 660px、手机 88vw，任意放大都不糊，位置在页面正中。
  - 标语“以人文铸科技”拆成六个字，**开局完全在屏幕左边界之外**（最右的字也压在弧的端点外），随滚动沿弧自左向右滚入，过边界才淡入；字串滚到弧顶附近时逐字飞向页面中心，组装成两行大字（“科技”为红）。
- **01 章节换成 CubeXDesktop**：窗口里**直接跑原软件的渲染层**（把 `CubexDesktop/out/renderer` 的构建产物复制到 `site/cubex-app/`，用同源 iframe 以 1120×700 加载，整体 `scale` 到容器宽度）。不做仿画、不截屏，界面就是软件本体。
  - 演示脚本抹掉应用写死的 `data-theme`（官网只展示深色），并隐藏 `浏览器预览` 徽标、预览模式提示、`配置模型` 这类只在浏览器预览里出现的状态标注；隐藏滚动条，`pointer-events:none` 让 iframe 不抢页面滚动。
  - 因为同源，`cubex.js` 能拿到 iframe 里的真实 DOM。底色（shell 背景、整列侧栏面板、主区粒子场）从一开始就在，画面是一个**空白的软件窗口**；滚动时界面上 14 个部件——侧栏品牌、模式胶囊、新建任务、自动化、项目分组、项目列表、设置、标题栏视图标签、两个工具按钮、三个窗口按钮、欢迎区字标/标题/副文案、输入区——各自从窗口右边界之外飞进来，落位后清空内联样式，恢复成软件自己的排版。
  - 起点统一算成「整块左边缘越过窗口右边界 +56px」，出界部分被 iframe 自己裁掉，所以看到的是每一块真的从画面外进来，不是原地抖一下。`aside.sidebar` 原本 `overflow:visible`，但 `nav.sidebar-scroll` 是 `overflow:auto`，会把飞出去的子元素裁掉，演示样式里把它放开。
  - 飞行中挂一张「承载卡」（伪元素：深灰渐变底 + 1px 描边 + 大投影），`--fly` 变量在最后 16% 路程收淡到 0，落位时和位移一起归零。又宽又矮的块（字标、标题、副文案，以及 712 宽的输入区）**裸飞不挂卡**：它们的宽度会把自己撑成一条空卡；输入区本身已有底和描边，也不需要再包一层。
  - 侧栏与标题栏的部件走纯水平推进（它们在同一列/同一行里排队，再错开就会在半空互相压字），主区三块带 ±0.7° 与 4–10px 偏移，纵向用 `f²` 收口，轨迹是一道很浅的弧。
  - 速度曲线是三次方减速、**不回弹**（早先用 back-out 会冲过落点 6%，400px 宽的块冲过头就是「压到旁边那块」）。出发进度按 0.042 步长错开（0.02 → 0.71），画面里始终三四块在空中，全部就位后一道高光扫过窗口。
  - 桌面把左栏收窄到 `.56fr`、右栏 `.1.44fr`，窗口占满右列，控件才看得清；窄屏单列并铺满两边。左侧四行功能说明 + 两个按钮不变。
- **导航状态机**：页顶展开 → 下滚收起成小胶囊（只剩 logo 与菜单键）→ 上滚展开。
- 产品卡去掉状态标签，CubexDesktop / CubexTeam 用真实 logo。
